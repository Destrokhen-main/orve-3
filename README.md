# Orve

Фронтенд-фреймворк на сигналах с JSX. Без виртуального DOM в привычном смысле:
JSX-узел — это плоский объект-описание, а сопоставление с DOM делает один общий
реконсилятор. Рантайм-зависимостей нет.

- реактивность в стиле Vue: `state` / `computed` / `watch` / `effect` / `effectScope`;
- два режима компонента: **базовый** (перерисовка через диффинг) и **сингл**
  (точечные обновления, render вызывается один раз);
- собственный JSX-рантайм — babel-плагин не нужен, достаточно `jsxImportSource`;
- плагины и `provide`/`inject` для роутера, стора, i18n и прочего.

> Библиотека молодая: нет SSR/гидрации, `<Portal>`, `<Suspense>`, анимаций
> переходов, делегирования событий.

---

## Установка

```bash
pnpm add orve
```

В `tsconfig.json`:

```json
{
  "compilerOptions": {
    "jsx": "react-jsx",
    "jsxImportSource": "orve"
  }
}
```

Если JSX разбирает esbuild/vite напрямую (`.jsx`-файлы без `tsc`), то же самое
в `vite.config`:

```ts
export default defineConfig({
  esbuild: { jsx: "automatic", jsxImportSource: "orve" },
});
```

Никаких алиасов и плагинов больше не нужно.

## Быстрый старт

```tsx
import { createInstance, state } from "orve";

const Counter = () => {
  const count = state(0);

  return () => (
    <button onClick={() => count.set((v) => v + 1)}>
      нажато {count.value} раз
    </button>
  );
};

createInstance().rootComponent(Counter).mountRoot("#app");
```

## Реактивность

```ts
import { state, computed, watch, effect, untrack, nextTick } from "orve";

const count = state(0);
count.value;              // чтение с подпиской
count.get();              // то же самое, вызовом
count.peek();             // чтение без подписки
count.set(5);             // запись
count.set((v) => v + 1);  // запись через апдейтер

const double = computed(() => count.value * 2);  // ленивый: считается при чтении

watch(() => console.log(count.value), [count]);  // явные зависимости
effect(() => console.log(count.value));          // авто-трекинг, запуск сразу

untrack(() => count.value);   // прочитать, не подписываясь
await nextTick();             // дождаться, пока применятся обновления
```

### `get()` — чтение с преобразованием

`get()` — это `.value`, только вызовом. А если передать функцию, она получит
текущее значение и вернёт то, что нужно в этом месте:

```ts
const status = state<"foo" | "baz">("foo");

status.get();                                   // "foo" | "baz"
status.get((v) => v === "foo");                 // boolean
status.get((v) => (v === "foo" ? bar : qwer));  // typeof bar | typeof qwer
```

Выходной тип выводится из вашей функции, поэтому результат остаётся
типизированным и с ним удобно работать дальше:

```tsx
const user = state({ name: "аня", admin: false });

<span class={() => user.get((u) => (u.admin ? "badge badge--admin" : "badge"))}>
  {() => user.get((u) => u.name.toUpperCase())}
</span>
```

- функция обязана вернуть значение на всех ветках — иначе в тип попадёт
  `undefined`, и TS об этом скажет;
- подписка встаёт на само состояние: функция — просто преобразование
  прочитанного;
- результат не кешируется, функция считается на каждом чтении. Нужен ленивый
  общий пересчёт — берите `computed`.

### `reactive()` — мутации по месту

`state` сравнивает по ссылке: мутировать объект и переприсвоить его же — то же
самое, что не менять ничего. Когда данные удобнее менять на месте, есть
`reactive()`: глубокий прокси, где подписка идёт по каждому свойству.

```ts
import { reactive, toRaw, markRaw, isReactive } from "orve";

const store = reactive({ list: [1], user: { name: "аня" } });

effect(() => console.log(store.user.name, store.list.length));

store.user.name = "оля";   // перезапустит эффект
store.list.push(2);        // и это тоже
```

- вложенные объекты оборачиваются лениво, на первом чтении;
- поддержаны обычные объекты, массивы, `Map`, `Set`, `WeakMap`, `WeakSet` —
  включая `size`, `for...of`, `Object.keys`, добавление и удаление ключей;
- `Date`, `RegExp`, DOM-узлы и замороженные объекты не оборачиваются;
- `toRaw(value)` — исходный объект: наружу (в сторонние библиотеки, в ключи
  `Map`, в сравнения по ссылке) отдавай именно его;
- `markRaw(obj)` — не оборачивать никогда. Нужно инстансам классов с приватными
  полями (`#x`): через прокси такие поля не читаются;
- подписка на свойство создаётся только при чтении: эффект, читающий `store.a`,
  не проснётся от записи в `store.b`.

`state` и `reactive` спокойно сочетаются: `state` — для значений целиком,
`reactive` — для структур, которые правят по месту.

В **сингле** render выполняется один раз, поэтому прокси надо читать внутри
тонка — иначе значение застынет:

```tsx
<b>{() => store.user.name}</b>          {/* ✅ обновляется точечно */}
<b>{store.user.name}</b>                {/* ❌ прочитано один раз */}

<For each={() => [...list]} by={(t) => t.id}>   {/* ✅ копия читает длину и индексы */}
<For each={() => list}>                          {/* ❌ ни одно свойство не прочитано */}
```

Полезные детали:

- обновления батчатся в микротаске — несколько `set` подряд дают один прогон;
- `state(v, { equals: false })` — не сравнивать значения, срабатывать всегда;
- `computed(fn, { deps: [a, b] })` — явные зависимости вместо авто-трекинга.
  В `deps` кладутся не только `state`/`computed`: объект от `reactive()` даёт
  подписку на всё его содержимое вглубь (`deps: [store]`), а геттер сужает её
  до одной ветки (`deps: [() => store.user.name]`);
- `watch(...)` возвращает объект с `.un()`, `.pause()`, `.resume()`; изменения
  во время паузы догоняются одним вызовом;
- `effectScope()` владеет созданными внутри эффектами: `scope.stop()` гасит всё
  сразу. Внутри компонента это делается за вас — при размонтировании.

## Компоненты

Компонент — функция, которая возвращает функцию рендера:

```tsx
const Hello = () => {
  // setup: выполняется ОДИН раз
  return () => <div>привет</div>;  // render
};
```

Тело компонента (`setup`) выполняется один раз при монтировании. Размонтирование
гасит все созданные в нём эффекты.

### ⚠️ Пропсы нельзя деструктурировать

Самая частая ошибка. `setup` выполняется один раз, поэтому любая
деструктуризация читает значение в этот единственный момент и замораживает его.

```tsx
// ❌ text прочитан один раз — обновления не придут никогда
const Badge = ({ text }: { text: string }) => () => <div>{text}</div>;

// ❌ то же самое
const Badge = (props: { text: string }) => {
  const { text } = props;
  return () => <div>{text}</div>;
};

// ✅ читаем в момент рендера
const Badge = (props: { text: string }) => () => <div>{props.text}</div>;
```

Это касается и `{ ...props }`, и `Object.assign`, и передачи `props` в функцию,
которая разбирает его внутри. `props.a.b` читать можно.

Если пропсы нужно передать дальше целиком — есть `forwardProps` (см. ниже).

Наружу можно передавать и значение, и сигнал — внутри компонента `props.x`
всегда обычное значение:

```tsx
<Badge text="ок" />
<Badge text={someSignal} />   // разворачивается автоматически
```

### Хуки жизненного цикла

```tsx
import { onMounted, onBeforeUnmounted, onUnmounted } from "orve";

const Widget = () => {
  onMounted(() => {/* узлы уже в документе — можно мерить, вешать слушателей */});
  onBeforeUnmounted(() => {/* DOM ещё на месте, эффекты живы */});
  onUnmounted(() => {/* узлы сняты, эффекты остановлены */});

  return () => <div />;
};
```

Вызывать только в `setup`. `onMounted` срабатывает ровно один раз за жизнь
инстанса, дети — раньше родителей.

### Проброс пропсов: `forwardProps`

Обёртка, которая принимает пропсы и отдаёт их дальше — в другой компонент, в тег
или в `jsx(...)` — не может ни разложить `props`, ни сделать `{ ...props }`.
Для этого есть `forwardProps`: плоская копия пропсов с возможностью выкинуть
служебные ключи.

```tsx
import { forwardProps, jsx } from "orve";

const Layout = (props: { is: ComponentFn; title: string }) => {
  // ❗ только внутри render — здесь читаются значения пропсов
  return () => jsx(props.is, forwardProps(props, ["is"]));
};
```

```ts
forwardProps(props, skip?)   // skip — массив ключей, которые не копируются
```

- **Вызывать только в render или в тонке, никогда в `setup`.** `forwardProps`
  читает значения пропсов; сделанная в `setup` копия снимется один раз и
  застынет — ровно как обычная деструктуризация.
- В render это безопасно: чтение подписывает render (или тонк) на все
  скопированные пропсы, поэтому при изменении любого из них копия пересоберётся.
  Ключи из `skip` не читаются — подписки на них не будет.
- Копия плоская и по значению; ребёнок получает обычные пропсы, его `setup` от
  этого не перезапускается.

Так устроен и встроенный `<Component>`: он отдаёт вниз `forwardProps(props, ["is"])`.

## Два режима

### Базовый (по умолчанию)

`render` обёрнут в эффект: изменилась реактивность — функция вызывается заново,
новое дерево диффится со старым, в DOM уходит разница.

```tsx
const Counter = () => {
  const count = state(0);
  return () => <span>{count.value}</span>;   // ЗНАЧЕНИЕ
};
```

- в слотах пишутся значения (`count.value`);
- условия и списки — обычный JS (`&&`, `map`), структура дерева свободная;
- спискам нужен `key`, иначе узлы сопоставятся по позиции.

### Сингл

```tsx
import { defineOptions } from "orve";

const Counter = () => {
  defineOptions({ single: true });
  const count = state(0);
  return () => <span>{count}</span>;          // СИГНАЛ
};
```

`render` вызывается ровно один раз. Обновляется только то место, куда попал сам
сигнал или тонк (`{() => expr}`).

- `{count.value}` здесь вычислится один раз и застынет — нужен `{count}`;
- структура дерева статична: обычный `if`/`map` отработает единожды. Динамика —
  через `<If>`, `<For>`, `<Component>`.

### Какой выбрать

Базовый — привычнее и проще, подходит почти везде. Сингл — когда важна
минимальная работа с DOM: длинные списки, часто меняющиеся значения, крупные
статичные деревья. Режимы свободно смешиваются: базовый родитель может держать
сингл-ребёнка и наоборот.

## Правила JSX

| Что | Как читается |
|---|---|
| `{"текст"}`, `{42}`, `{null}` | статический текст |
| `{signal}` | реактивный слот — **только в сингле** |
| `{() => expr}` | реактивный слот-тонк — **только в сингле** |
| `class={signal}`, `class={() => …}` | реактивный атрибут (работает в обоих режимах) |
| `onClick={fn}` | **всегда обработчик**, никогда не тонк |
| `onClickCapture={fn}` | обработчик в фазе перехвата |
| `onClick={[fn, { once: true }]}` | обработчик с опциями слушателя |
| `ref={fn}` / `ref={signal}` | доступ к DOM-узлу; при размонтировании приходит `null` |
| `key={…}` | идентичность узла в списке |

Если передать сигнал в слот базового компонента, в консоли появится
предупреждение `[orve]`, а значение будет прочитано как обычное — это подсказка,
что вы перепутали режим.

`class` принимает строку, массив (falsy отбрасывается) или объект
`{ имя: условие }`. `style` — строку или объект (camelCase → `kebab-case`,
`--custom` как есть). `value`, `checked`, `innerHTML` и подобные ставятся как
DOM-свойства. `<svg>` и `<math>` со своим неймспейсом поддерживаются, регистр
атрибутов вроде `viewBox` сохраняется.

## Встроенные компоненты

```tsx
import { If, For, Component } from "orve";
```

### `<If>`

```tsx
<If when={isOpen} then={() => <Modal />} else={() => <span>закрыто</span>} />
```

`when` принимает значение, сигнал или тонк.

### `<For>`

```tsx
<For each={todos} by={(todo: Todo) => todo.id}>
  {(todo: State<Todo>, i: State<number>) => (
    <div style={() => `font-weight: ${todo.value.done ? "bold" : "normal"}`}>
      {() => todo.value.name}
    </div>
  )}
</For>
```

Колбэк вызывается **один раз за жизнь строки** и получает `item` и `index`
сигналами. При изменении массива уцелевшие строки не пересобираются — им просто
пишется новое значение, и обновляется ровно та часть DOM, которая его читает.

Два важных следствия:

- **`by` практически обязателен** для списков объектов. Без него идентичность
  строки — ссылка на элемент, и иммутабельное обновление
  (`list.map(t => ({ ...t }))`) пересоздаст все строки.
- **Мутация элемента на месте не видна** — сравнение идёт по `Object.is`.
  Обновляйте заменой: `copy[i] = { ...copy[i], done: true }`.

Свой `key` внутри `For` не нужен — идентичностью строк владеет сам `For`.
Проп называется `by`, а не `key`, потому что `key` забирает JSX-рантайм.

### `<Component>`

Динамически подставляет компонент, тег или готовый узел и пробрасывает внутрь
все остальные пропсы, включая `children`:

```tsx
const current = computed(() => (page.value === 1 ? Basic : Single));

<Component is={current.value} user={user.value} />
```

Сменился `is` — старое поддерево размонтируется, новое встаёт на место. Тот же
`is` с новыми пропсами — `setup` не перезапускается, обновляются только пропсы.

`is` принимает компонент, имя тега (`is="section"`), готовый узел (`is={<Card />}`)
или сигнал/`computed`, но **не тонк**: компонент сам является функцией, поэтому
`is={Card}` и `is={() => Card}` неразличимы. Для вычисляемого выбора —
`is={computed(() => flag.value ? A : B)}`.

Если пропсы прокидывать не нужно, `Component` тоже не нужен: узел — обычный
`Child`, кладите его прямо в слот.

## provide / inject

Передать значение всем потомкам без проброса через пропсы:

```tsx
import { provide, inject } from "orve";

const key = Symbol("theme");

const Parent = () => {
  provide(key, { color: "red" });
  return () => <Child />;
};

const Child = () => {
  const theme = inject<{ color: string }>(key);
  return () => <div style={{ color: theme?.color }} />;
};
```

Оба вызова — только в `setup`. Значение обычное, не реактивное (положите туда
сигнал, если нужна реактивность). `inject(key, defaultValue)` вернёт `default`,
если наверху ничего не нашлось.

## Плагины

Плагины кладут что-то общее (роутер, стор, i18n) в контекст, видимый из любого
компонента, вне зависимости от места в дереве.

```ts
const instance = createInstance()
  .use(routerPlugin, { base: "/app" })
  .use((cx, api) => {
    cx.$store = createStore();
    api.onUnmounted(() => cx.$store.dispose());
  })
  .rootComponent(App)
  .mountRoot("#app");
```

```tsx
import { usePlugin } from "orve";

const Page = () => {
  const router = usePlugin("$router");
  return () => <a onClick={() => router.push("/next")}>дальше</a>;
};
```

Плагин — это функция `setup` или объект `{ name?, setup }`. `setup` вызывается
один раз, синхронно, в момент `use()`; возвращённая из него функция работает как
cleanup.

```ts
const timerPlugin = {
  name: "timer",
  setup(cx) {
    const id = setInterval(tick, 1000);
    cx.$timer = { stop: () => clearInterval(id) };
    return () => clearInterval(id);
  },
};
```

Второй аргумент `setup` — `api`:

| Член | Назначение |
|---|---|
| `name` | имя плагина |
| `options` | второй аргумент `use(plugin, options)` |
| `instance` | сам инстанс — можно доставить зависимый плагин |
| `provide(key, value)` | типобезопасная альтернатива мутации контекста |
| `has(name)` | установлен ли другой плагин |
| `onMounted(fn)` | после монтирования корня |
| `onUnmounted(fn)` | при `instance.unmount()` |

Доступ из компонентов (только в `setup`):

| Функция | Поведение |
|---|---|
| `usePlugins()` | весь контекст |
| `usePlugin(key)` | одно значение или `undefined` |
| `requirePlugin(key)` | то же, но бросает, если плагина нет |
| `hasPlugin(key)` | тихая проверка |

Что стоит знать:

- плагины ставятся в порядке `use()`, каждый следующий видит контекст предыдущих;
- повторная установка того же плагина (по ссылке или имени) пропускается с warn;
- ошибка в `setup` не роняет инстанс и не оставляет мусора в контексте;
- гашение идёт в обратном порядке установки;
- плагин, поставленный после `mountRoot()`, в уже созданных компонентах не появится.

### Типизация

```ts
declare module "orve" {
  interface OrvePlugins {
    $router: Router;
  }
}
```

После этого `usePlugin("$router")` вернёт нормальный тип, а не `unknown`.

const instance = createInstance()

## Шпаргалка по экспортам

- Реактивность: `state`, `computed`, `watch`, `effect`, `untrack`, `effectScope`,
  `getCurrentScope`, `onScopeDispose`, `nextTick`, `flushSync`
- Компоненты: `onMounted`, `onBeforeUnmounted`, `onUnmounted`, `defineOptions`,
  `provide`, `inject`, `forwardProps`
- Встроенные: `If`, `For`, `Component`
- Инстанс и плагины: `createInstance`, `usePlugins`, `usePlugin`, `requirePlugin`,
  `hasPlugin`
- Типы: `State`, `Computed`, `Reactive`, `MaybeReactive`, `Child`, `VNode`,
  `ComponentFn`, `Render`, `Props`, `CSSProperties`, `ClassValue`, `EventHandler`
